# Git subprocess失敗時の診断記録

> 作成日: 2026-11-19
> 更新日: 2026-11-19
> 作成者: Codex

## 適用

Git子プロセスが起動できない、異常終了する、timeoutする、または出力の検査に失敗した場合に使います。ここでは、失敗処理を識別して、後から試行や原因を追跡できる情報をrunの診断記録へ残します。共通原則は[エラー時の診断記録ポリシー](../error-diagnostic-recording-policy.md)に従います。

## 記録手順

1. **処理段階と操作を識別する。** 失敗した処理段階の安定したstage名と、安全なコマンド識別子（例: git.diff.cached.check）を記録します。実行したコマンドの生文字列や完全な引数列を、通常の診断記録へ転記しません。パス、URL、ブランチ名などが秘匿情報を含み得る場合も除外します。
2. **プロセス結果を記録する。** 終了コードが得られた場合はその数値を記録します。例外が起きた場合は型名を記録します。timeout、起動失敗、キャンセルなど終了コードを得ていない場合は、その状態を区別します。例外メッセージやstack traceは、安全性を確認せず保存しません。
3. **実行と出力を相関させる。** 失敗を観測した時刻をISO 8601（UTCのZまたは明示的なオフセット）で記録します。既存run IDを使い、別プロセスやイベント間の相関が必要な場合にcorrelation IDを記録します。stdoutとstderrについて有無・長さを記録し、長さの単位（byteまたは文字）と切り詰め状態を明示します。Git porcelain出力が状態判定の入力になる場合、出力本文・ファイルパスは残さず、パーサーが認識した状態コード別件数、状態レコード数、byte/文字長、観測開始・終了時刻を記録できます。porcelainの形式を安全に解析できない出力を推測で分類しません。
4. **安全な診断だけを残す。** 出力から必要最小限の診断断片を抽出し、秘密情報・個人情報・非公開パス等をマスキングまたは除去してから記録します。安全に除去できたと確認できない場合は本文を残さず、reason code、エラー分類、長さ、機密を含まない短い要約、または適切な場合に限り安全性を確認したハッシュで代替します。出力全文を一律に保存しません。
5. **再現調査の経緯を記録する。** 再現条件、実施した試行と各結果、原因を判断する根拠、未確認事項と残る不確実性を、事実と仮説に分けて記録します。仮説を確認済み原因として報告しません。
6. **生アーティファクトを選別する。** snapshot用Git index、一時作業領域、完全なdiffは無条件に保存・添付しません。必要性を確認し、安全な要約や識別子で代替できない場合に限り、アクセス制限された専用領域へ保存します。保存した場合は診断記録に安全な参照と必要性を記し、閲覧権限・保持・削除を管理します。
7. **保存失敗を別途扱う。** 診断記録の書き込みが失敗しても元のGit失敗を隠さず、成功扱いにしません。安全な最小情報を呼び出し元またはstderrへ返せる場合は、stage、reason code、run/correlation ID等に限って通知します。記録できなかった項目と証跡の欠落を最終報告に明記します。

## 完了時の報告

- 記録できた事実（stage、コマンド識別子、終了コードや例外、出力の有無・長さ）と原因仮説を分けます。
- 再現できない場合は、試行した条件・結果を示し「再現不可」とします。再現不可だけで解決済みと判断しません。
- 調査を終了した場合は、受入条件の達成状況、未解決のリスク、後続対応、Issueの状態をそれぞれ明示します。
