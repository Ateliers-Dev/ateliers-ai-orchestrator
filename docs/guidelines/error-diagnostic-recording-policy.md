# エラー時の診断記録ポリシー

> 作成日: 2026-11-19
> 更新日: 2026-11-19
> 作成者: Codex

## 目的と位置付け

この文書は、エラー時の診断記録で共通して守る原則を定め、ケース別の具体的な記録方法を案内する索引です。特定のコマンドやエラーごとの詳細手順はここに集約せず、[診断記録方法](diagnostic-recording-method/README.md)に置きます。診断記録方法には、エラー以外の診断手順も格納できます。

## 共通方針

- 調査目的に必要な情報を選び、既存の構造化診断と保存先を優先します。平常時の詳細ログ、stdout/stderr全文、環境一式を一律に採取しません。
- 診断情報は、利用できる範囲で機械処理可能な形にし、既存のフィールド名・意味・上限を維持します。不足情報だけを追加し、重複したログや記録形式を増やしません。
- 観測した事実、そこからの推論・仮説、未確認事項を分けます。値を取得できない場合は推測で補わず、未取得または該当なしと記録します。
- 秘密情報・個人情報・非公開パス等をログへ出さないよう、記録前にマスキングまたは除去し、閲覧範囲を調査に必要な担当者と運用者に制限します。アクセス制限は、ログ本文への機密保存を許す理由にはなりません。
- 機密を安全に除去できない場合は、本文を保存せず、エラー分類、reason code、長さ、機密を含まない短い要約などで代替します。ハッシュはそれ自体から秘密や本文が推測できない場合に限り、必要性とアクセス範囲を確認して使います。
- 記録は既存run記録等の保存先・保持・削除方針に統合します。不要な複製や無期限保存を避け、保持方針が確認できない場合は運用者へ確認・報告します。
- 診断記録の保存に失敗しても元の処理エラーを隠したり、成功扱いへ変えたりしません。可能なときは安全な最小情報で保存失敗を通知し、失われた証跡を報告します。
- 調査を終えたこと、受入条件を満たしたこと、Issueを解決・クローズしたことを混同しません。原因が未特定の場合も、残るリスクと未達事項を明示します。

## ケース別の診断方法

具体的な手順は、必要な情報だけを扱う独立した文書として [診断記録方法](diagnostic-recording-method/README.md) に置きます。

| ケース | 手順の概要 |
|---|---|
| Git subprocessの失敗 | [Git subprocess失敗時の診断記録](diagnostic-recording-method/git-subprocess-failure.md): 処理段階と安全なコマンド識別子、終了コード・例外、時刻・run/correlation ID、stdout/stderrの有無・長さ、安全な診断内容、再現条件・試行・未確認事項を記録します。生の引数やsnapshot indexは無条件に保存しません。 |

新しい診断手順を追加するときは、対象ケースに固有の情報だけを手順書に記載し、この索引と診断記録方法READMEへリンクを追加します。手順書は共通方針と矛盾しないようにします。
