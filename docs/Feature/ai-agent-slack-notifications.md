# AIエージェントのSlack通知機能

> 作成日: 2026-11-21
> 更新日: 2026-11-21
> 作成者: yuu503

## AIエージェントとは

AIエージェントは、依頼された作業を担当し、成果をまとめるAIの作業担当者です。Ateliers AI Orchestratorは、作業全体の進行役として、担当者へ依頼を渡し、結果を受け取ってRunの状態や最終結果をまとめます。

## 役割を分けて作業する

現在のワークフローでは、主に次の役割を使います。

- **Implementer（実装担当）**: 依頼に沿ってコードなどの変更を行い、成果を提出します。
- **Reviewer（レビュー担当）**: 変更内容を確認し、問題や追加対応が必要かを報告します。
- **Orchestrator（進行役）**: 依頼の条件と実行状態を管理し、担当者の作業や最終結果をまとめます。

役割（Role）は「何を担当するか」、Agent IDは「どのAgentか」を示します。たとえば、同じReviewerという役割にも、コード確認やセキュリティ確認など専門分野を持たせられる設計です。複数担当者をどう選んで動かすかは今後の拡張事項です。

## Agentごとの設定と個性

合意済みの設計では、Agentごとに安定したID、表示名、担当Role、使用モデル、個別の指示を設定ファイルで管理します。全員に共通する指示、Slack報告の共通ルール、Agent個別の文体や観点を別の文書に分ける考え方です。

この構成により、同じ作業Roleでも、説明の仕方や注目する点に個性を持たせられます。ただし、個性を付けても、上位の安全ルールや共通の報告項目は省略できません。

**現在、このAgent設定一式と個別指示の読込機能は実装されていません。** 詳細設計と暫定JSON例は[Agent設定と指示管理](../reference/agent-configuration-and-instructions.md)を参照してください。

## Slackで作業結果を知らせる

目指す設計では、Agentが作業を終えたときに、自分の言葉で完了報告を作ります。Orchestratorはその内容を受け取り、担当Agentに対応するSlack Botを使って通知します。Slackへの接続情報や秘密情報はOrchestrator側で扱い、Agentには渡しません。

Run（ひとまとまりの実行）ごとにSlackのスレッドを作り、開始、担当者の進捗、作業完了、最終状態をまとめます。加えて、Runの最終結果はチャンネルにも投稿し、スレッドを開かなくても結果を把握できる形を目指します。

**現在の通知は固定形式のライフサイクル通知です。** Agentが生成した個性ある完了文、Runごとのスレッド、最終結果のチャンネル投稿は未実装です。通知の設計と現在の動作は[Slack通知設計](../reference/slack-notifications.md)に記載しています。

## 何を期待できるか

Orchestratorは実行条件やワークフロー状態を管理しますが、AIの判断が常に正しいことを保証するものではありません。実施した確認と、まだ確認できていないことを区別して結果を扱います。最終結果やレビューは人が確認して判断することがあります。
