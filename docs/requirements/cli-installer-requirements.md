# CLIインストーラー要求仕様

> 状態: 承認済み。Phase 1 の実装・受入基準。

## 1. 目的

Ateliers AI Orchestrator のRelease CLIをユーザー環境へ一度インストールし、MCPから毎回リポジトリをclone・buildせずに実行できるようにする。

## 2. 対象と前提

- 対象はAteliers AI Orchestrator CLIのRelease配布物である。
- CLI実行バージョンを固定し、MCPが実行するバージョンを一意に解決できること。
- インストールはユーザー単位とし、`%LOCALAPPDATA%\Ateliers-Dev\Ai-Orchestrator` を使用する。CLI実行ファイルと配布ファイルはその `bin` 配下に置く。
- 管理者権限を必要としないユーザー領域へのインストールを要件とする。
- 初期配布対象は Windows x64 とし、自己完結型 Release ZIP を用いる。ユーザー設定が必要な場合のみ Roaming を使い、LocalLow は使わない。
- CLIの実行物と実行時データ（実行記録、ログ、作業領域、設定）は混在させない。

## 3. 機能要求

1. インストーラーは、指定されたReleaseバージョンのCLIと実行に必要なファイルを、確定済みのユーザー単位インストール先へ配置する。
2. インストール完了後、MCPがそのインストール済みバージョンを解決できる安定した識別情報を提供する。
3. 実行対象のバージョンは暗黙に最新版へ移動せず、インストール時に選択・記録された固定バージョンとする。
4. 更新は明示的なインストールまたは更新操作として行い、どのバージョンが実行対象になったかを確認可能にする。
5. CLIとMCPはそれぞれ固定バージョンで管理し、更新は各コンポーネントの明示的な操作で行う。既存契約インターフェースとの互換性が維持される場合は独立して更新でき、一方の更新を理由に他方の再ビルドまたは再インストールを要求しない。
6. インストーラーは、MCPや親AIによる各実行時のソースclone・buildを前提にしない。
7. インストール後に、配置先とバージョンを確認できる手段を提供する。
8. インストール時のバージョンは必須の明示指定とし、インストーラーはGitHub Releaseの該当タグ配布物を取得する。`latest` を解決して自動追従してはならない。
9. CLI自身が実行中バイナリの埋め込みバージョンを表示し、インストーラーは配布マニフェスト、インストール記録、CLIの表示を照合する。

## 4. 運用・品質要求

- インストール先はユーザー単位で分離され、他ユーザー領域への書き込みを前提にしない。
- 再実行時に、既存ファイルを無関係な内容で破壊しない。更新動作と同一バージョン再インストールの結果を明示する。
- インストールが失敗した場合、失敗状態と利用者が確認可能な理由を示し、不完全な状態を成功として報告しない。
- MCPは、固定バージョンの実行対象が存在しない、または起動不能な場合にその状態を判別できる。
- リリース配布物の入手元と真正性検証の方法は、実装前に既存のRelease運用を確認し仕様に記録する。
- Release ZIPと同じGitHub ReleaseにSHA-256ファイルを添付し、ダウンロード後に照合する。これは転送・破損検出用で、同一Release権限が改ざんされた場合に独立した署名者を検証する仕組みではない。
- 更新は一時ディレクトリへ展開・検査してから `bin` を切り替える。同一バージョンの再インストールも明示操作として許可する。切り替え確認が失敗した場合は既存 `bin` を復元する。

## 5. 受入条件

- 管理者権限なしで、選択されたReleaseバージョンをユーザー単位の確定先へ配置できる。
- 配置された実行ファイルと記録されたバージョンが一致する。
- MCPが参照するCLI実体とバージョンを特定できる。
- バージョンが意図せず自動更新されない。
- CLIとMCPのバージョンが個別に固定され、更新が明示的に行われる。
- 既存契約インターフェースとの互換性が維持される範囲で、一方の更新を理由に他方の再ビルド・再インストールを要求しない。
- インストール失敗または欠損を、成功と区別できる。
- 利用者が配置先とバージョンを確認できる。
- 指定バージョンのZIPとSHA-256が検査され、バージョン不一致・欠損・展開・切替・実行確認の失敗を非ゼロ終了と利用者可読なエラーで報告する。

## 6. 初期版の境界

この仕様はユーザー単位の固定バージョン配置を対象とする。複数バージョンの切り替えUI、自動更新、全ユーザー向けインストール、MCP自身のオーケストレーション実装は要求に含めない。更新失敗時には直前の `bin` を復元するが、任意バージョンの履歴保持やロールバックUIは対象外とする。
