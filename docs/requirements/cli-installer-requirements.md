# CLIインストーラー要求仕様（案）

> 状態: ユーザー確認用の草案。承認前のため、実装要求としては未確定。

## 1. 目的

Ateliers AI Orchestrator のRelease CLIをユーザー環境へ一度インストールし、MCPから毎回リポジトリをclone・buildせずに実行できるようにする。

## 2. 対象と前提

- 対象はAteliers AI Orchestrator CLIのRelease配布物である。
- CLI実行バージョンを固定し、MCPが実行するバージョンを一意に解決できること。
- インストールはユーザー単位とし、`%LOCALAPPDATA%` 配下を第一候補とする。インストール先の最終パスは本仕様確認時に確定する。
- 管理者権限を必要としないユーザー領域へのインストールを要件とする。
- 対応OS、配布形式、インストーラーの具体形式は、既存のRelease運用と整合させて確認する事項とする。

## 3. 機能要求

1. インストーラーは、指定されたReleaseバージョンのCLIと実行に必要なファイルを、確定済みのユーザー単位インストール先へ配置する。
2. インストール完了後、MCPがそのインストール済みバージョンを解決できる安定した識別情報を提供する。
3. 実行対象のバージョンは暗黙に最新版へ移動せず、インストール時に選択・記録された固定バージョンとする。
4. 更新は明示的なインストールまたは更新操作として行い、どのバージョンが実行対象になったかを確認可能にする。
5. インストーラーは、MCPや親AIによる各実行時のソースclone・buildを前提にしない。
6. インストール後に、配置先とバージョンを確認できる手段を提供する。

## 4. 運用・品質要求

- インストール先はユーザー単位で分離され、他ユーザー領域への書き込みを前提にしない。
- 再実行時に、既存ファイルを無関係な内容で破壊しない。更新動作と同一バージョン再インストールの結果を明示する。
- インストールが失敗した場合、失敗状態と利用者が確認可能な理由を示し、不完全な状態を成功として報告しない。
- MCPは、固定バージョンの実行対象が存在しない、または起動不能な場合にその状態を判別できる。
- リリース配布物の入手元と真正性検証の方法は、実装前に既存のRelease運用を確認し仕様に記録する。

## 5. 受入条件

- 管理者権限なしで、選択されたReleaseバージョンをユーザー単位の確定先へ配置できる。
- 配置された実行ファイルと記録されたバージョンが一致する。
- MCPが参照するCLI実体とバージョンを特定できる。
- バージョンが意図せず自動更新されない。
- インストール失敗または欠損を、成功と区別できる。
- 利用者が配置先とバージョンを確認できる。

## 6. 初期版の境界

この仕様案はユーザー単位の固定バージョン配置を対象とする。複数バージョンの切り替えUI、自動更新、全ユーザー向けインストール、MCP自身のオーケストレーション実装は要求に含めない。サイドバイサイド保持やロールバックの要否は、既存Release運用と更新方針を確認して承認時に決める。
